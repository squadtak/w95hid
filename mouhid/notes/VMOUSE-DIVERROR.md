# 起動時の VMOUSE 割り算エラー(要確認・間欠)

状態: **対策を入れたが原因は未確認。たまに起きる問題なので、再発するか様子を見る。**

## 症状

USB マウスを挿したまま電源を入れると、起動中に次のエラーが出ることがある。

```
an exception 00 has occurred at 0028:c02a3d25 in vxd vmouse(03) + 00000c89
this was called from 0028:c02a3a88 in vxd vmouse(03) + 000009ec
```

例外 00 = 割り算エラー(#DE)。OSR2.1 の `VMOUSE`(VMM32.VXD 内)のオブジェクト 3 の中。

## 見立て(未検証)

- MOUHID は `VMD_Post_Pointer_Message` でポインタ入力を渡している。
- 起動の早い段階では VMOUSE の内部状態(感度、座標の比率など)が未初期化で、
  割る数が 0 のまま呼ばれた可能性がある。起動後のホットプラグでは起きていない。
- 割る数の出どころは未確認(OSR2.1 の VMOUSE の逆アセンブルができていない)。

## 入れた対策(mouhid.c / mouhid.asm)

- `KERNEL32_INITIALIZED`(0x31)を受けるまでは、マウスのレポートを VMOUSE に渡さず捨てる(`g_Ready`)。
- 起動からかなり後に読み込まれた場合(ホットプラグ)は 0x31 を受けないので、
  読み込み時またはレポート受信時の Windows 起動からの経過時間(`Get_System_Time`)が 90 秒以上なら準備完了とみなす。
- 副作用: 0x31 の後なのに起動から 90 秒以内にホットプラグすると、90 秒まではマウスが動かない。

## 再発したときに調べること

1. 発生のタイミング: マウスを動かしていたか、ボタンを押していたか、起動の何秒ごろか。
2. 例外アドレスが毎回同じか(`+00000c89` / `+000009ec`)。違えば別の原因。
3. OSR2.1 の `VMOUSE.VXD` を取り出して(`WINDOWS\SYSTEM\VMM32.VXD` から展開、または VMM32 フォルダ内の個別ファイル)、
   `tools/ledump.py` で `+0xc89` 周辺を逆アセンブルし、`div` / `idiv` の割る数の出どころを見る。
   (参考: `w98usbdrv/vmouse.vxd` は Win98 版でオフセットが違う。)
4. 割る数が VMOUSE の初期化中の変数なら、`KERNEL32_INITIALIZED` では早すぎ/遅すぎの可能性があるので、
   ゲートの条件(例えば最初のマウスメッセージを VMOUSE が処理した後、`VMD_Get_Mouse_Data` で状態を見る)を見直す。
5. 他の入力(VKD へのキー注入)で同様のことが起きていないか(今のところキーボードでは未確認)。
